# LogiFlow 0.12.8

## 로그온 전환 — `setHost 전송 0개` / 중복 워커 수정 (핵심)

디버그 로그에서 확인: 트리거는 터지는데(`[로그온 전환] → 채널 1`) 같은 순간 `setHost 전송 0개`·`전송 2개`가 **번갈아** 찍혔다.

원인: 로그온 워커가 **둘 이상 동시 실행**(토글 켤 때마다·ONSTART 로 새 워커가 뜨고 옛 워커가 안 죽음). 두 워커가 HID 를 서로 물어, 한쪽은 시작 스캔에서 기기를 못 잡아 `전환가능 0개`→`전송 0`, 다른 쪽은 `2개` 스캔 성공→`전송 2`. 실제 전환은 2개 쪽이 하므로 "되긴 되는데" 로그가 지저분하고 경합 위험.

수정:

- **워커 단일 인스턴스 보장**(`Global` 뮤텍스): 이미 돌고 있으면 새 워커는 바로 종료 → HID 경합 제거.
- **전송 직전 switchable 비어 있으면 1회 즉석 재스캔**: 시작 스캔이 경합으로 비었어도 전환 순간 다시 잡아 보냄.

> 재부팅 후 워커 1개만 돈다(기존에 떠 있던 SYSTEM 워커는 재부팅으로만 정리됨 — 사용자 권한 taskkill 로는 못 죽임).

## 참고 — dwell=0.00 은 정상

전환이 한 번 터진 뒤 커서가 변에 박힌 채 `dwell=0.00` 으로 머무는 건 **재전환 방지(재무장)** 동작이다. 커서가 변에서 16px 떨어졌다 다시 와야 재무장된다. 전환이 실제로 되면 마우스가 반대 PC 로 넘어가므로 문제 없음.
