# LogiFlow 0.12.12

## 콜드부팅 로그인 전 전환만 안 되던 문제 — 원인 가림 + 웨이크·확인·재시도

회장님 실측으로 범위가 정확히 좁혀졌다:

- **로그인 후 Win+L 잠금화면**: 마우스·키보드 둘 다 **빠르게 잘 전환됨** ✓
- **콜드부팅(로그인 한 번도 안 한) 로그온 화면**: **아무것도 안 넘어감** ✗ — 이것만 남음.

로그엔 `setHost 전송`이 찍혔는데도 안 넘어갔다 = **OS 는 출력 리포트를 받아들였지만 기기가 채널을 안 바꿈**. 로그인 전엔 리시버가 입력(커서·타이핑)은 넘기지만 HID++ 명령 파이프가 덜 깨어 setHost 가 무시되는 상태로 보인다.

이번 판:

- **기기별 전환 결과를 보이는 로그에 표시** — 각 기기마다 `시도N 쓰기=성공/실패 확인=현재채널 X/응답없음 → 전환됨/미전환`. 콜드부팅에서 쓰기가 되는지, 기기가 실제로 채널을 바꾸는지(getHostInfo 재조회로 확인)가 드러난다.
- **웨이크(ping) + 확인 + 재시도(최대 3회)** — setHost 전에 HID++ ping 으로 명령 파이프를 깨우고, 전환 후 getHostInfo 로 현재 채널을 확인, 안 바뀌었으면 150ms 간격으로 재시도. (전환되면 기기가 사라져 응답이 없는 게 정상 → 성공으로 판정.)
- 안전 가드(0x1814 지원·채널 범위)와 단일 쓰기 경로(HidppDevice.SetHost)는 그대로. Win+L·트레이 전환 경로는 변경 없음(기존 SwitchAll 유지).

## 적용·시험

0.12.12 설치 → 설정 "로그온 전에도 실행" 껐다 켜기 → **콜드부팅**. 로그온 화면에서 마우스 깨워 변으로 밀기. 로그에 기기별 `시도1 쓰기=… 확인=… → 전환됨/미전환` 이 뜬다. 그 줄(마우스·키보드 각각)을 주시면:

- 재시도로 전환되면 완성.
- 여전히 `쓰기=성공 확인=현재채널 그대로 → 미전환` 이면, 로그인 전 HID++ 명령 파이프의 OS/드라이버 한계가 확정 — 그때는 "콜드부팅은 1회 로그인 필요(그 뒤 Win+L 은 됨)"로 정직하게 문서화하거나 다른 접근(리시버 직접 명령)을 검토한다.
