# LogiFlow+ (B안) — 서비스 단일 전담 작업 계획

브랜치 `logiflow-plus`. **지금까지 한 건 다 그대로 두고 전환 로직만 B로 바꾼다.**
목표 = 로그인 직후 데스크탑 공백 0 (트레이 뜨는 틈 제거).

## 핵심 아이디어

지금(main): 서비스 워커는 **Winlogon(로그온/잠금) 데스크톱만** 감시. 사용자가 로그인해
입력 데스크톱이 Default(바탕화면)로 바뀌면 워커는 "OFF(사용자 세션 담당)"로 물러나고
그 자리를 트레이 앱(EdgeWatcher)이 맡음 → **그 교대 틈이 공백**.

B안: 전환 감시 주체를 **서비스 워커 하나로 단일화**. 바탕화면에서도 서비스 워커가 계속
전담. 트레이 앱은 전환 감시를 끄고 **설정·수동전환·glow UI 전용**으로 축소. 교대가 없으니
공백 0, 중복 전환도 원천 제거.

## 바꿀 자리(main 코드 기준)

- `Diagnostics/DesktopProbe.cs` `LogonSwitchLoop` L508-512:
  `bool secure = name!="Default"; bool active = secure || locked;` →
  **Default 에서도 active=true** (모든 입력 데스크톱 전담).
- `TrayAppContext.cs` / `Handoff/EdgeWatcher`: 트레이의 엣지 전환 감시 **비활성**
  (설정·수동전환·glow 는 유지). 서비스가 안 깔렸을 때의 폴백 여부는 결정 필요.

## 단계

- **B-1 전환 주체 단일화**: 서비스 워커 Default 포함 전담 + 트레이 엣지 감시 비활성.
  중복 전환 제거. (공백 0 달성, 단 바탕화면 판정 품질은 B-2 전까지 폴링 한계)
- **B-2 바탕화면 오작동 방지(raw input 이식)**: 서비스 워커가 Default 에선
  **raw input + MinPushPx**(의도적 밀기만)로 판정. 지금 바탕화면 오작동 방지를 위해
  트레이가 쓰던 로직을, 서비스-스폰 워커(winsta0\default, message-only 창 + WM_INPUT)에
  이식. Winlogon 은 폴링+dwell(MinPushPx=0) 유지(로그온 화면은 커서 클램프라 밀기 못 읽음).
- **B-3 상태 공유·정리**: glow·활성·별칭을 머신 공유 설정으로 서비스 워커와 공유,
  트레이는 UI 전용. QA 조합(콜드부팅/로그인/잠금/화면보호기/사용자전환) 전수.

## 품질 트레이드오프(B-1 바탕화면 판정)

폴링(GetCursorPos)+dwell 은 **화면 끝에 박힌 커서의 '바깥으로 미는 물리 이동'을 못 읽는다**
(클램프됨). 그래서 로그온 화면은 dwell-only(MinPushPx=0)로 "변에 머물면 전환". 이 방식을
바탕화면에 그대로 쓰면 **커서를 우측 끝에 두고 작업(스크롤바 등)만 해도 전환**되는 오작동.
제대로 막으려면 raw input(물리 밀기)이 필요 = B-2. → B-1 을 폴링으로 먼저 올리면 "전환은
되는데 오작동 가능", raw input 부터 제대로 하면 "작업 크지만 오작동 최소".

## 리스크

- 서비스가 사용자 데스크탑에 상시 프로세스 상주(보안 표면↑).
- 데스크탑 전환 타이밍 레이스(winlogon↔default↔screensaver).
- 릴리스는 여전히 main 만. 브랜치는 빌드·실기 테스트용.
