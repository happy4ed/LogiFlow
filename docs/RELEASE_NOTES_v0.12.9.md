# LogiFlow 0.12.9

## 부팅 때 로그온 워커가 안 뜨던 진짜 원인 = 배터리 (핵심)

`schtasks` 진단으로 확정: 예약 작업이 **"배터리가 사용되는 경우 시작 안 함"** 기본값을 갖고 있었다. ARM 은 노트북이라 **부팅 시 배터리 상태** → ONSTART 트리거가 **거부됨** → 워커 미실행 → 로그 없음. 토글을 껐다 켜면 `/Run`(수동 즉시 실행)이 이 조건을 무시해 그제서야 동작한 것("직접 켜야만 된다"의 정체).

수정 — 예약 작업을 XML 로 생성하도록 바꿔 다음을 보장:

- **배터리 조건 제거**(`DisallowStartIfOnBatteries=false`·`StopIfGoingOnBatteries=false`) → 배터리로 부팅해도 뜸.
- **트리거 2중화(부팅 + 로그온)** → 부팅 때 못 떠도 **로그인하면 무조건 뜸**. 회장님이 관찰한 "한번 로그온해야 실행된다"에 맞춤.
- 중복은 0.12.8 단일 인스턴스 뮤텍스가 차단(부팅·로그온 둘 다 떠도 워커는 하나).

## 토글 표시 버그 수정

"로그온 전에도 실행"을 껐는데 재시작하면 다시 켜져 보이던 문제: OFF 처리 때 삭제 성공을 낙관하지 않고 **실제 작업 존재 여부를 재조회**해 표시·저장하도록 고침.

## 기능 자체는 검증됨

0.12.8 로그에서 잠금화면(Winlogon·locked) 오른쪽 변 밀기 → `[로그온 전환] → 채널 1` + `setHost 전송` 확인. 이번 판은 **그 워커가 부팅/로그인 때 자동으로 뜨게** 만드는 수정이다.

## 적용법

설치만으론 예약 작업이 안 바뀐다 — 설치 후 **설정 → "로그온 전에도 실행" 껐다 켜기**(이때 새 2중 트리거 작업이 생성됨). 그다음부터는 **부팅·로그인 때 자동**으로 워커가 뜬다.

## 유지

- 0.12.8 단일 인스턴스·전송 직전 재스캔, 0.12.7 MinPushPx=0·ProgramData 워커 복사 그대로.
