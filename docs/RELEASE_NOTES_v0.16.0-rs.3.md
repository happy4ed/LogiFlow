# LogiFlow 0.16.0-rs.3 — Windows 러스트 시험판(실기 대기)

**정식 아님 — 회장님 PC 확인용 시험판.** rs.2 에 처음 쓰는 사람 점검 20건과 코드 리뷰에서 남겨 둔 3건을 고친 판. C# 판(0.15.0)과 나란히 설치된다.

회장님 원문(main 중계): "일단 다 고쳐서 포팅해줘봐". 이 20건에 한해 계획서의 「화면 C# 1:1」 원칙을 풀었다. 그 밖의 화면·동작은 rs.2 그대로다.

## 받을 파일

| 파일 | 내용 |
|---|---|
| `LogiFlowRs-v0.16.0-rs.3-setup.exe` | 설치 파일(x64·ARM64 한 파일, PC 에 맞는 쪽 설치) |
| `LogiFlowRs-v0.16.0-rs.3-win-x64-arm64.zip` | 실행 파일만 |

받는 곳: `rust-port` 브랜치 GitHub Actions 실행 페이지의 아티팩트(로그인 필요). 릴리스(Latest)에는 올리지 않음.

## 화면 — 처음 쓰는 사람 점검 20건

점검은 고칠 때마다 다시 돌렸다(2차 18건 → 3차 14건 → 4차 10건 → 5차 4건 → 6차 6건(하 5) → 7차). 아래는 최종 모양 기준.

### 글 잘림(6건)

글을 고정 높이 상자에 넣던 방식을 버리고, 남는 폭에서 줄바꿈하며 줄·카드·창 높이가 글에 맞춰 늘어나게 바꿨다. 단추 폭·높이도 글자에 맞춰 커진다. 글자 크기(작게·보통·크게) 세 단계 모두 CI 화면 캡처(27장)로 확인했다.

1. 진단 — 로그인 화면 테스트 안내 셋째 줄 잘림 → 안내 글과 1·2·3 단계로 나눠 줄바꿈.
2. 설정 — 「로그인 전에도 실행」 설명 오른쪽 잘림 → 줄바꿈.
3. 「상세 디버그 로그」 설명 잘림 → 줄바꿈(진단 「기록」으로 옮기며 이름은 「상세 기록」).
4. 「글자 크기」 설명 둘째 줄이 카드 테두리에 잘림 → 카드 높이를 내용에 맞춤.
5. 캔버스 아래 줄 채널 상자의 상태 글자 잘림 → 아래 줄을 글자 한 줄만큼 위로.
6. 크게 단계에서 「대기」 글자와 입력 칸이 붙음 · 모니터 칸 글자 꽉 참 → 「머무는 시간」 줄로 바꾸고, 모니터 칸은 들어가는 줄만 그림.
- 2차 점검에서 더 나온 것: 「작게」를 골라도 설명 글 크기가 그대로였음(C# 의 최소 9.5pt 에 「작게」·「보통」이 둘 다 걸림) → 모든 글자를 1pt 키워 작게 9.5 · 보통 10.5 · 크게 12.5pt 로 단계가 보이게.
- 3차 점검에서 더 나온 것: 설명 안 「단추 이름」이 줄 끝에서 둘로 쪼개짐 · 줄 끝에 「·」만 남음 → 그 둘은 줄바꿈하지 않음. 6차: 「PC 로」처럼 영문 낱말 뒤 조사만 다음 줄로 떨어짐 → 붙여 둠. 크게 단계에서 테마·글자 크기 선택 칸이 꽉 참 → 칸 폭이 글자에 맞춰 넓어짐.

## 코드 리뷰에서 남겨 둔 3건

1. 서비스가 켜진 채 「끌기 중 전환 막기」·채널 배치·머무는 시간을 바꾸면 워커를 다시 띄우지 않아도 반영 — 바탕화면 워커는 1초마다 `logon-edges.txt` 수정 시각을 보고, 로그인 화면 워커는 4초마다 다시 읽는다. 트레이는 이 파일을 임시 파일에 쓴 뒤 바꿔 끼운다(반쯤 쓴 파일을 읽지 않게).
2. HID 원시 쓰기는 코어 밖에서 할 수 없다 — `HidTransport::write` 는 코어만 만들 수 있는 `OutReport`(리포트 내용)를 빌려 받는다. Windows 어댑터·설정 창은 보낼 바이트를 정할 수 없고, 받은 리포트를 보관했다가 나중에 다시 보낼 수도 없다.
3. 호스트 수를 모르는 기기(getHostInfo 무응답)에는 아무것도 보내지 않는다(C# 은 이때 범위 검사를 건너뜀). 화면·트레이·가장자리 경로는 원래 호스트 수가 확인된 기기만 쓰므로 실제 동작 차이는 없다.

### 2차 코드 리뷰(codex)에서 더 고친 것

1. 쓰기 허가를 「허가표」 대신 「리포트 자체」로 — 어댑터가 허가표를 보관했다가 임의 내용으로 다시 쓰는 우회를 막음(위 2).
2. `logon-edges.txt` 바꿔 끼우기가 실패하면 원본에 직접 덮어쓰던 대체 경로를 없앰(반쯤 쓴 파일을 워커가 읽지 않게).
3. 바탕화면 워커가 시작 준비 중에 바뀐 설정을 놓치지 않게 수정 시각을 먼저 잡음.
4. 방화벽 「허용됨」은 지금 포트가 열려 있을 때만(규칙 이름만 같고 포트가 다르면 「허용 안 됨」), 「허용 해제」 결과는 지우기 명령의 결과로 판단.
5. 로그인 화면 테스트 기록에 잠금 표시(`locked=Y`)를 남겨, ARM 처럼 잠금 화면이 Default 로 보이는 PC 도 바르게 판정.
6. 이 PC 주소는 설정 화면을 열 때마다 다시 조회(와이파이·VPN 으로 바뀐 경우).

C# 판과 주고받는 형식은 바뀌지 않았다 — 클립보드 프레임(CI 의 .NET 대조 통과) · `config.txt` · `devices.txt` 형식 그대로.
